> このアクションは **Linux ランナー専用** です (`ubuntu-latest`、`ubuntu-22.04` など) 。
> Windows・macOS はサポートしていません。

## リファレンス

このページでは、`get-changed-files` アクションの入力パラメーター・出力値・パターン書式・制約事項を説明します。
`get-changed-files` はトリガーイベントで変更されたファイルを取得し、glob パターンで絞り込みます。

---

## アクション基本情報

ワークフローから以下のように参照します。

```yaml
steps:
  - uses: actions/checkout@v7.0.1
    with:
      fetch-depth: 0 # 必須
  - id: changed
    uses: aglabo/ci-platform/.github/actions/ca-get-changed-files@v0.6.0
    with:
      pattern: |
        **/*.md
        !docs/**
  - if: steps.changed.outputs.count != '0'
    env:
      CHANGED_FILES: ${{ steps.changed.outputs.files }}
    run: printf '%s\n' "$CHANGED_FILES"
```

> 実際に使用する際には最新バージョンのタグを指定し、`gh actions-lock` でロックファイルを更新してください。

### 前提条件

- `actions/checkout` は `fetch-depth: 0` で実行してください。
- 対象リポジトリは作業ディレクトリ (`GITHUB_WORKSPACE`) に checkout してください。`actions/checkout` の `path` は指定しないでください。
- partial clone (`filter` を指定した checkout) はサポートしていません。エラーになります。

## 入力パラメーター

| パラメーター   | 型     | 必須   | デフォルト | 説明                                                                |
| -------------- | ------ | ------ | ---------- | ------------------------------------------------------------------- |
| `commit-count` | string | いいえ | `1`        | `HEAD~N` 範囲で使うコミット数 N (1〜1000)                           |
| `pattern`      | string | いいえ | ``         | glob パターン (1 行に 1 つ)。`!` で始まる行は除外。空欄はすべて残す |

### `commit-count`

`push` で使える before SHA がない場合と、`push` / `pull_request` 以外のイベントで、`HEAD~N..HEAD` の N として使います。

補足:

- `1`〜`1000` の正の整数のみ有効です。`0`・先頭のゼロ (`01`)・`+`・空白を含む値はエラーになります。
- 値の検証は、イベントの種類を問わず最初に行います。`push` や `pull_request` で N を使わない場合も、不正な値はエラーになります。

### `pattern`

1 行に 1 つの glob パターンを書きます。パターンはリポジトリルートからの相対パス全体と照合します。

```yaml
with:
  pattern: |
    **/*.md
    !docs/**
```

補足:

- 各行の前後のスペースとタブは取り除かれ、空行は無視されます。
- `#` で始まる行はコメントではありません。通常のパターンとして扱います。
- 大文字と小文字は区別します。

#### パターン書式

| 書式         | 意味                                                             | 例                               |
| ------------ | ---------------------------------------------------------------- | -------------------------------- |
| `*`          | `/` 以外の 0 文字以上                                            | `*.md` はルート直下の `.md` のみ |
| `?`          | `/` 以外の 1 文字 (UTF-8 の 1 文字)                              | `v?.txt`                         |
| `**`         | 単独で書くとすべてのパス                                         | `**`                             |
| `**/`        | 先頭または `/` の直後で、0 個以上のディレクトリ                  | `**/*.md` はすべての `.md`       |
| `/**` (末尾) | `/` と 1 文字以上 (ディレクトリをまたぐ)                         | `docs/**` は `docs` 配下のすべて |
| `!` (行頭)   | 除外パターン。先頭の `!` を 1 つだけ取り除いたパターンで照合する | `!docs/**`                       |

補足:

- `[...]` は文字クラスではありません。`[`・`]`・`{`・`}`・`.` などの記号はその文字そのものに一致します。
- `*` と `?` はドットファイル (`.github` など) にも一致します。
- 上記以外の位置の `**` は `*` と同じ扱いです (例: `**.sh`) 。
- `dir/**` は `dir` 自体には一致しません。`src` のようにディレクトリ名だけ書いても、`src/a` には一致しません。
- 先頭の `/` は文字として扱うため、`/foo` はどのパスにも一致しません。

#### 判定順

- 各ファイルについて、**最後に一致したパターン** の種類 (含める / 除外) で判定します。
- どのパターンにも一致しないファイルは、最初のパターンが除外パターンなら残し、含めるパターンなら除きます。
  そのため、除外パターンだけを書くと「指定したもの以外すべて」になります。
- `pattern` が空の場合は、変更されたファイルをすべて残します。

## 比較範囲

イベントの種類によって、比較するコミット範囲を決めます。

| イベント          | 比較範囲                                          | 補足                                                              |
| ----------------- | ------------------------------------------------- | ----------------------------------------------------------------- |
| `push` (ブランチ) | `github.event.before` → `github.sha`              | before が存在しないコミットの場合は `HEAD~N` 範囲に切り替える     |
| `pull_request`    | `pull_request.base.sha` → `pull_request.head.sha` | merge-base は使わない                                             |
| 上記以外          | `HEAD~N` → `HEAD`                                 | `pull_request_target`・`workflow_dispatch`・`schedule` などを含む |

補足:

- `push` の before SHA が空・すべてゼロ (新規ブランチ)・force push などで到達できない場合は、エラーにせず `HEAD~N..HEAD` を使います。
- `pull_request` は base と head を直接比較します。PR の作成後に base ブランチだけで変更されたファイルも含まれることがあります。
- `pull_request_target` は既定で base ブランチを checkout するため、PR の変更ではなく base ブランチの直近 N コミットが対象になります。
- `HEAD~N` が存在しない場合、first-parent の履歴が N 以下なら空のツリーと比較します。このとき `HEAD` のすべてのファイルが変更ファイルになります。
  shallow clone (`fetch-depth: 1` など) でもこの扱いになるため、`fetch-depth: 0` を指定してください。

### 変更ファイルの種類

`git diff --name-only --diff-filter=ACMR` で一覧を取得します。

| 種類                 | 扱い                   |
| -------------------- | ---------------------- |
| 追加・変更           | 含める                 |
| 名前の変更           | 変更後のパスのみ含める |
| 削除                 | 含めない               |
| 種類の変更・未マージ | 含めない               |

## 出力値

| 出力名  | 値     | 説明                                                                   |
| ------- | ------ | ---------------------------------------------------------------------- |
| `files` | 文字列 | 残ったファイルのパス (1 行に 1 つ、末尾の改行なし)。ない場合は空文字列 |
| `count` | 文字列 | 残ったファイル数の 10 進数 (先頭ゼロなし)。ない場合は `0`              |

補足:

- `files` の並び順は `git diff` の出力順のままです。
- 一致するファイルが 0 件でもエラーにはなりません。後続のステップは `count` で判定してください。
- 非 ASCII のパスは UTF-8 のまま出力します。

### 出力値の参照方法

```yaml
- if: steps.changed.outputs.count != '0'
  env:
    CHANGED_FILES: ${{ steps.changed.outputs.files }}
  run: |
    while IFS= read -r file; do
      echo "changed: $file"
    done <<<"$CHANGED_FILES"
```

`files` は `run` に直接展開せず、環境変数経由で渡してください。

## 制約事項

| 制約               | 内容                                                       | 備考                       |
| ------------------ | ---------------------------------------------------------- | -------------------------- |
| checkout           | `fetch-depth: 0` で、`GITHUB_WORKSPACE` に checkout する   | アクション側では検査しない |
| partial clone      | サポートしない                                             | エラー                     |
| push               | ブランチ削除の push と、タグの push はサポートしない       | エラー                     |
| `commit-count`     | 1〜1000 の正の整数                                         | エラー                     |
| 変更ファイル数     | 最大 3000 行・120000 バイト                                | 超えるとエラー             |
| `pattern`          | 最大 100 行・120000 バイト                                 | 超えるとエラー             |
| 除外パターン       | `!` だけの行、`!` の直後に空白がある行はエラー             | エラー                     |
| 特殊文字を含むパス | `"`・`\`・タブ・改行などの制御文字を含むパスは処理できない | エラー                     |
| 改行コード         | CRLF は LF として扱う。LF を伴わない CR を含む入力はエラー | エラー                     |

補足:

- エラーはすべて `::error::<対象>: <内容>` の形式で 1 行出力し、アクションを失敗させます。
